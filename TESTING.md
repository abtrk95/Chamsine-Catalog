## Scope and limitations

Browser navigation was unavailable in the execution environment. Tests therefore loaded the actual HTML/CSS and application code into an offline DOM harness, injecting only module transport, fixture fetch/images/storage, and native-share/download callbacks. This validates DOM behavior and generated PDF bytes but **does not** certify a deployed HTTPS site, HTTP/module MIME types or caching, CSP, real storage persistence after browser restart, actual download handling, or the WhatsApp app receiving an attachment.

Only Chromium was exercised; WebKit/Safari and Firefox were not run. Mobile viewport tests are simulated layouts, not physical phone tests. No live WhatsApp message was sent. The publication helper was syntax-checked, dry-run checksum-checked, and exercised with a mocked GitHub API; the full remote upload was not executed.

## Required release smoke check

After deploying the complete folder over HTTPS, open a fresh tab, verify only the PIN field appears, enter 0102, and verify product images/load-more/filtering/cart/variant selection. On real iOS Safari and Android Chrome, choose a priced and unpriced product, send the order, select WhatsApp, and inspect the attached PDF before sending it. Cancel sharing once and confirm the cart remains. On a browser without file sharing, verify the saved PDF and the explicit manual-attachment instruction. Check a multi-page order and a quantity greater than one. Confirm source draft items and missing prices/SKUs are acceptable before release.

## Reproduce the offline browser checks

With Python Playwright and Chromium installed, run `python3 tests/browser_offline.py`. Set `CHROMIUM_PATH` when Chromium is not on PATH. The harness injects offline transports as described above and saves previews into ignored `test-artifacts/`. Native OS sharing is mocked, never sent. The publisher checks run with `python3 tests/publish_test.py`.
